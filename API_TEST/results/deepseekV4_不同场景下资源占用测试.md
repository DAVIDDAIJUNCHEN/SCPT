## 一、核心结论

**总体评价**：推理服务在各类负载下运行稳定，GPU 利用效率与 prompt 长度正相关，并发能力均衡，超长上下文场景 GPU 利用率急剧下降，瓶颈转移至内存/PCIe 带宽。

**关键发现**：

- **GPU 利用率呈现明显的"长度依赖"特征**：长 prompt（99.2%）> 中 prompt（94.7%）> 短 prompt（74.6%），短 prompt 场景下 GPU 有约 25% 空闲（数据依据：吞吐量测试 9 轮均值）。
- **并发 1~64 范围内 GPU 利用率均保持在 90% 以上**，未出现明显的并发瓶颈，仅在并发 8（89.8%）和并发 32（90.2%）时小幅下降（数据依据：并发测试 9 轮均值）。
- **上下文超过 128K tokens 后 GPU 利用率断崖式下跌**：131K 降至 40.0%（且第 8 轮出现 GPU 数据缺失），1M 仅 9.9%，表明推理瓶颈从计算转向存储/传输（数据依据：上下文测试 8 轮均值）。
- **GPU 显存全程恒定 136.6 GB**，无波动，服务未发生显存溢出或动态扩缩（数据依据：全部 9 轮 199 个测试项 gpu_mem_mean_mb 均为 139828.0 MB）。
- **CPU 持续满载**（全程 99.9%~100.1%），CPU 成为固定开销基线（数据依据：全部测试 sys_cpu_mean_% 范围）。
- **系统内存使用稳定在 85.9~86.3 GB**，波动仅约 0.4 GB，未出现内存泄漏迹象（数据依据：全部测试 mem_used_mean_mb 范围）。
- **上下文 2048 tokens 测试稳定性较差**：多轮出现 GPU 利用率大幅波动（7.0%~100.0%），与极短测试时长（部分轮次仅 0s，1 个采样点）有关（数据依据：8 轮上下文 2048 测试数据）。

**简要分析**：

- 上下文超过 32K 后 GPU 利用率呈单调下降趋势：32K（66.9%）→ 65K（52.9%）→ 131K（40.0%）→ 1M（9.9%）。
- **1M tokens 场景 GPU 利用率仅 9.9%**，GPU 大部分时间处于空闲状态，瓶颈已完全转移至 KV Cache 加载与内存带宽。
- 第 8 轮 131K 上下文测试 GPU 数据为 null，可能为 dmon 采集异常，建议排查该轮监控链路。
- 内存占用在所有上下文长度下保持恒定（86.0~86.1 GB），未观察到随上下文增长而显著上升的趋势。

### 长上下文 GPU 利用率偏低的原因

1M token 时 GPU 利用率均值仅约 10%（本轮测试为 9.9%），这不是系统故障，而是大语言模型长上下文推理的固有架构特性。推理过程分为 Prefill（一次性处理全部输入、构建 KV Cache）和 Decode（逐步生成 token）两个阶段。Prefill 阶段的瓶颈是显存带宽而非算力——GPU 需要将数 TB 级别的 KV Cache 数据在显存和计算单元之间搬运，导致计算单元大量空闲，表现为 GPU 利用率骤降。待 KV Cache 构建完毕后进入 Decode 阶段，利用率即刻恢复至 100%。这一现象在 DeepSeek 官方 API 及其他 LLM 推理系统中同样存在，属于正常的工程行为，不构成性能缺陷。
