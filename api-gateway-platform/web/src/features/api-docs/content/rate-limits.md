# 02-3 限流与容量

> 川邮·星语 API 开发者手册 · 信息核实日期 2026-09-26
> 平台已于 **2026-09-24 启用 API 层限流**：按分组限制「每分钟请求数」，超限返回 429（指数退避重试即可）。本页说明限流规则、各模型并发上限、满载行为，以及您的代码该怎么写。

## API 层限流（2026-09-24 起）【实测 2026-09-24】

| 分组 | 每 1 分钟请求数上限 |
|---|---|
| default（注册默认） | **100** |
| vip | **300** |

- 计数窗口 1 分钟，滚动重置；超出上限的请求返回 **429**，报文带 `retry_after` 提示。
- 限流按**账号分组**计，不按令牌——同一账号多把令牌共享额度。
- 压测实测：220 并发冲击下 89 个成功（200）+ 131 个被限流（429），保护生效、零宕机。
- 个人正常使用（对话/长文/课堂演示）远达不到上限；仅代码 bug 死循环调 API 时才会触发。

## 长文用户必读：等待时间以分钟计

1M 上下文容量是「**同时在处理**」的上限，不是「秒回」承诺：

- 8 万字输入 ≈ **10 秒**内开始作答【实测 2026-09-23】
- 100 万字输入 ≈ **6.5 分钟**后才开始作答【实测，prefill 2.5K token/s】
- 多条长文同时提交时共享读取带宽，等待时间相应延长

**建议**：整班课堂演示百万字长文时，错峰提交（每组间隔 1~2 分钟），避免全班同时命中 6 分钟等待。

## 满载时会发生什么（压测验收数据）

2026-09-23 以 200 并发冲击 DS-V4.1-Flash 全链路的实测结果：

| 指标 | 实测值 |
|---|---|
| 成功返回 | 176 / 200（88%） |
| 被拒绝的 24 个 | 全部 503「排队满」**优雅拒绝，零数据丢失、零宕机** |
| 502 网关错误 | **0 个** |
| 撤压后恢复 | **15 秒**回到基线延迟 0.21s |

结论：**平台过载时是「变慢/排队/礼貌拒绝」，不会崩溃，不会丢失已在处理的请求**。您的代码只需正确处理 503 重试即可。

## 给开发者的重试建议

```python
import time

def call_with_retry(fn, max_retries=3):
    for i in range(max_retries):
        try:
            return fn()
        except Exception as e:
            # 503 排队满 / 429：指数退避后重试
            # 401/404：不重试，直接修配置
            if "503" in str(e) or "429" in str(e):
                time.sleep(2 ** (i + 1))  # 2s → 4s → 8s
                continue
            raise
    raise RuntimeError("重试次数用尽，请稍后再试或联系智算中心")
```

**三类错误的重试策略**：

- **可重试**：503 排队满、429、500 —— 指数退避，最多 3 次
- **不可重试**：401、404、422 —— 修配置（令牌/模型名/参数）
- **不用重试**：502/SSL —— 挂证书即可，重试一万次也没用

## 课堂场景容量参考

按 1 路并发 ≈ 10~20 名轻交互师生折算【理论折算，锚点：人均每分钟 1~2 次请求 × 每次推理 10~20 秒】：

- 整班上课（50 人）：任意单模型都轻松承载
- 多班同时（200~300 人）：优先分散到不同模型；DS-V4.1-Flash 单模型可扛约 500~1000 人【理论折算】
- 全校日常：无算力瓶颈，注册容量按需开放
