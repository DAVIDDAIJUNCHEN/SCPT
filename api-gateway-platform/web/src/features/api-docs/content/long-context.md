# 1M 长上下文

> 数据：2026-09-23 实测。1M = 100 万 token ≈ 100 万汉字（1 token ≈ 1 汉字）。

## 支持模型

| 模型 | 单次最大输入 | 说明 |
|---|---|---|
| **DeepSeek-V4.1-Flash** | **1M** | 长文主力，同时可跑 27 条满量长文 |
| **Qwen3.8-Flash-Next** | **1M** | 中文长文优化 |
| **GLM-5.3-Flash** | **1M** | 轻量长文 |
| DeepSeek-V4-Flash-0731 | 1M | 上一代 |
| GLM-5.3（vip 分组） | 128K | 满血版不支持 1M（架构上限，非配置问题） |

## 等待时间（先读完才能作答）

长文请求需先完成"阅读"（prefill），第一个字才会输出。**输入越长，等待越久**：

| 输入长度 | 等待时间【实测】 |
|---|---|
| 8 万字 | 约 10 秒 |
| 97 万字 | 约 6.5 分钟 |

> 同一长文**重复提问**（如换着角度问同一份文档）会命中缓存，第二次起明显更快。

## 并发容量【实测】

| 场景 | DeepSeek-V4.1-Flash |
|---|---|
| 满量 1M（100 万字）长文同时进行 | **27 条** |
| 50 万字级 | 约 54 条 |
| 10 条长文 + 普通短对话 | 普通对话仍有约 38 路并发可用，师生基本无感 |

## 调用样例

```bash
curl https://ai-platform.sptc.edu.cn/v1/chat/completions -k \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $YOUR_API_KEY" \
  -d '{
    "model": "DeepSeek-V4.1-Flash",
    "messages": [
      {"role": "user", "content": "<这里粘贴整份长文档>\n\n请总结要点"}
    ],
    "max_tokens": 2000
  }'
```

长文直接放在 `content` 里即可，无需分段上传；`max_tokens` 建议按需设置（默认偏小可能截断长回答）。

## 使用建议

1. **整篇放入优于摘要后放入**——模型读原文的准确率显著高于读摘要。
2. 超过 100 万字的需求需拆分（如分章节多次提问，或先检索再精读）。
3. 网页版（星语 Chat）与 API 均支持 1M，无需特殊参数。
